# MaxFit

Компактный фитнес-сайт на React + TypeScript. Vinext (совместимый App Router), Vite, серверные маршруты и Cloudflare Workers. Дизайн адаптивный; логотип и иконки — собственные SVG.

## Запуск

Нужны Node.js >= 22.13 и pnpm версии из `package.json`.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm typecheck
pnpm test
pnpm build
```

Production-артефакты генерируются в `dist/`. Каталог не является исходным кодом. На другом хостинге нужен runtime для Cloudflare Workers либо перенос серверных адаптеров; это не статический HTML-экспорт.

## Где менять

- `app/page.tsx`, `components/maxfit/home.tsx` — страница и тексты.
- `app/globals.css` — стили, мобильная версия и анимации.
- `components/maxfit/icons.tsx` — фирменный знак и плавная иконка движения.
- `components/maxfit/booking-dialog.tsx` — форма и обработка ошибок.
- `lib/catalog.ts` — стабильные идентификаторы услуг.
- `lib/validation.ts` — серверная валидация входящих данных.
- `lib/server/database.ts` — адаптер хранения заявок.
- `lib/server/payments.ts` — контракт будущей платёжной интеграции.
- `app/api/*/route.ts` — серверный API.
- `db/schema.ts`, `drizzle/` — схема заявок и первая миграция.

## Текущее состояние

База и платёжный провайдер намеренно не подключены. `/api/status` возвращает `leadsEnabled: false` и `paymentsEnabled: false`. Форма готовит текст, но не сообщает об отправке. `/api/leads` и `/api/checkout` возвращают 503 при отсутствии интеграций. Онлайн-покупка на странице не отображается.

## Подключение базы

Предусмотрен адаптер Cloudflare D1. В `.openai/hosting.json` установите `d1: "DB"` вместо `null` и опубликуйте сайт: Sites создаёт binding и применяет миграции. Локальную базу нужно мигрировать отдельно. Для другой платформы создайте базу и binding `DB` в её конфигурации. Для Supabase/PostgreSQL замените только адаптер `lib/server/database.ts` и способ определения доступности.

После появления `DB` форма запрашивает контакт и согласие, а API сохраняет заявку. Повтор с тем же UUID не создаёт дубликат. Схема не создаётся внутри HTTP-запросов. Читать заявки публично нельзя: GET-маршрута для них нет. Админ-панель и уведомления тренеру пока не реализованы. До открытия публичного приёма заявок добавьте подходящие вашему хостингу ограничение частоты запросов и защиту от ботов, а также контакт владельца и политику обработки данных.

```sh
pnpm db:generate
```

При изменении схемы добавляйте новые миграции; не переписывайте применённые.

## Подключение оплаты

В `lib/server/payments.ts` реализуйте `PaymentProvider` выбранного провайдера и верните экземпляр из `getPaymentProvider()`. Контракт уже используется `/api/checkout`: принимает только serviceId, а не цену от посетителя. Перед подключением кнопок покупки необходимо:

1. Указать реальные цены и валюту; сопоставить serviceId с ценами на сервере.
2. Хранить ключи только в секретах хостинга, не в браузере, Git и публичных переменных.
3. Создавать hosted checkout через серверный адаптер с ключом идемпотентности.
4. Добавить таблицы заказов и платежей, webhook с проверкой подписи и защитой от повторной обработки событий.
5. Подтверждать оплату по webhook, не по возвращению пользователя на success-страницу.
6. Пройти тестовую оплату, отмену и повтор webhook. После этого включить интерфейс покупки и статус оплаты.

Сейчас адаптера конкретного провайдера и webhook нет. Наличие маршрута `/api/checkout` не означает, что можно принимать деньги.

## API

Изменяющие запросы требуют JSON, совпадающий Origin, UUID v4 в `Idempotency-Key`. Тело ограничено 8 КБ. Секреты и ошибки базы не возвращаются в ответах.

- `GET /api/status` — возможности текущего окружения.
- `POST /api/leads` — `{ name, contact, goal, serviceId, consent: true, website?: "" }`.
- `POST /api/checkout` — `{ serviceId }`.
